## Context

The project is a Vite React portfolio app. `vite.config.js` builds to `dist/`, uses `assets/` inside that output, and disables sourcemaps. `package.json` has `dev`, `build`, and `preview` scripts, with `package-lock.json` present. The current `.gitignore` only ignores `node_modules`.

## Goals / Non-Goals

**Goals:**

- Keep generated, machine-local, and sensitive files out of Git.
- Align ignored files with a Vite app that is intended to be deployed to GitHub Pages from source or a CI build output.
- Preserve files required to build and publish the site, including source code, `public/` assets, configuration, and lockfiles.

**Non-Goals:**

- Add or modify GitHub Actions workflows.
- Change Vite `base`, build output configuration, package scripts, or app code.
- Remove already-tracked files from the repository index during planning.

## Decisions

- Ignore `dist/` as generated output.
  - Rationale: Vite produces static assets in `dist/`; for GitHub Pages, this should usually be generated by a deploy step rather than committed with source.
  - Alternative considered: keep `dist/` tracked for manual Pages publishing. Rejected for this plan because the user asked to avoid uploading unnecessary files to GitHub.
- Ignore local environment files with `.env*` but explicitly allow `.env.example`.
  - Rationale: local environment values may be sensitive, while examples are useful documentation.
  - Alternative considered: ignore only `.env.local`; rejected because broader `.env*` coverage is safer for local secrets.
- Include common Node, Vite, editor, OS, cache, coverage, and log ignores.
  - Rationale: these are not needed for repository source or GitHub Pages publishing and are common accidental commits.
  - Alternative considered: keep a minimal ignore file; rejected because the current one is too narrow for the project tooling.

## Risks / Trade-offs

- `dist/` ignored while GitHub Pages is configured to publish from a branch folder manually -> Pages may not receive output unless a deploy workflow or equivalent process publishes it.
  - Mitigation: implementation should only change `.gitignore`; if deployment fails later, add a separate change for Pages workflow or branch strategy.
- A currently tracked generated file remains tracked even after `.gitignore` is updated.
  - Mitigation: implementation should check `git status` and, if needed, report any tracked generated output for a deliberate follow-up removal rather than silently deleting content.
